1. Executive Summary
The Client Communication Agent System is an AI-powered WhatsApp CRM platform designed specifically for Indian retail businesses. The system enables non-technical business owners to broadcast personalised messages to hundreds of clients and provides an intelligent, 24x7 client-facing assistant bot that answers questions about products, offers, and past communications — without requiring any human intervention.

5. System Architecture
5.1 Architecture Overview
All components run on a single Hetzner CX21 server via Docker Compose. Two independent agent pipelines share a common PostgreSQL database and ChromaDB knowledge base. All services are containerised for consistent dev and production environments.

Architecture Layers

5.2 Broadcast Flow
The broadcast flow handles all outbound messaging from the operator to clients:
Owner creates broadcast message on dashboard (template text, channel, schedule)
FastAPI backend validates, personalises message using LangGraph Broadcast Agent
Celery worker picks up the task from Redis queue
Messages dispatched to Gupshup API respecting rate limits (~80 msg/sec)
Delivery receipts (sent / delivered / read / failed) returned via Gupshup webhook
Results stored in broadcast_recipients table; dashboard updated in real time
Every broadcast message automatically indexed in ChromaDB for bot retrieval

5.3 Client Query Flow (RAG Pipeline)
The RAG pipeline handles all inbound messages from clients:
Client sends WhatsApp message; Gupshup posts it to /webhook/whatsapp
HMAC signature verified; message sanitised (HTML/script tags stripped)
Language detected (English or Hindi)
Rate limiting checked (max 20 messages per client per hour)
LangGraph Client Assistant Bot embeds query using text-embedding-3-small
ChromaDB semantic search returns top context chunks (active offers only via metadata filter)
LLM generates grounded response using retrieved context only (no hallucination mode)
Confidence score logged; responses below 0.75 auto-flagged for owner review
Reply sent back to client via Gupshup; conversation stored in PostgreSQL

5.4 Knowledge Base Ingestion
Every broadcast and uploaded document is automatically indexed for retrieval:
Owner uploads PDF, image, or text document via dashboard
FastAPI validates file; assigns category (products / offers / broadcasts / documents)
Text extracted and split into semantic chunks
OpenAI text-embedding-3-small generates vector embeddings
Stored in tenant-specific ChromaDB collection with metadata: tenant_id, category, valid_until, is_active
knowledge_base table updated in PostgreSQL with chroma_ids array

9. Feature Specifications
9.1 Broadcast Agent
Client Upload
Accepts Excel (.xlsx) or CSV files only — no database tools required for operator
Preview screen shows detected columns (name, phone, email) before confirming import
Duplicate phone numbers are skipped; count of imported vs. skipped shown to operator
Bulk opt-in flag can be set at import time

Message Creation
Template editor mirrors composing a standard messaging app message
Variables defined with {{1}}, {{2}} syntax (per WhatsApp template rules)
Real-time personalisation preview for a sample client record
Language selector: English or Hindi
Submit pre-approved template names for regulatory compliance

Scheduling & Sending
Immediate send or scheduled broadcast (date + time picker)
Send window restricted to 9am–7pm local time by default; override available
Maximum one broadcast per client per 24-hour period enforced at Celery task level
Celery worker dispatches messages via Gupshup API at up to 80 messages/second
Automatic retry logic for failed messages (up to 3 retries with exponential backoff)

Delivery Tracking
Real-time delivery report: Sent, Delivered, Read, Failed (plain-language labels)
Per-client breakdown downloadable as CSV
Webhook callbacks from Gupshup update delivery status automatically

9.2 Client Assistant Bot
Core Retrieval Behaviour
Answers only questions about products, offers, orders, and past broadcasts
Operates in retrieval-only mode — LLM cannot generate answers from general knowledge
If Chroma returns no relevant results, bot falls back gracefully without hallucinating
Active offers only — Chroma metadata filter ensures expired offers are never retrieved

Language Handling
Auto-detects language (English or Hindi) per message
Responds in the detected language of the client's query
All WhatsApp templates prepared in both languages

Safety & Abuse Protection
Rate limiting: max 20 inbound messages per client per hour; excess silently dropped and logged
Prompt injection guard: system prompt restricts bot to product/offer/order scope only
Input sanitisation: HTML, script tags, and excessive special characters stripped before processing
Out-of-scope deflection: bot responds politely and directs client to contact business directly

Escalation Path
Responses below 0.75 Chroma confidence score automatically flagged for owner review
Flagged messages visible in dashboard Flagged Inbox
Owner marks message as resolved after manual reply
If same question type flagged 3+ times in a week, owner prompted to upload covering document

9.3 Operator Dashboard
Onboarding Flow (8 Steps)
First login: guided setup wizard — business name, logo, default language
Upload client list: Excel/CSV, preview columns, confirm import
Opt-in confirmation: bulk set opted_in = true after owner confirms consent
Upload first document: at least one product PDF or offer — confirms indexing
Test broadcast: send to owner's own number; review personalised message on WhatsApp
Test the bot: owner sends WhatsApp message to business number; reviews bot response
Review flagged messages: owner taught to resolve flagged conversations
Go live: first real broadcast to 10–20 clients; expand after reviewing delivery report

10.3 WhatsApp Quality Rating Safeguards

10.4 Compliance Rules
Opt-in mandatory: broadcasts only sent to clients with opted_in = true. Enforced at Celery task level — cannot be overridden from dashboard.
Opt-out: client replies of STOP, UNSUBSCRIBE, or NO set opted_in = false within 30 seconds via webhook.
Template only: outbound messages to clients who have not messaged first must use approved templates.
Frequency cap: maximum one broadcast per client per 24-hour period.
Send window: 9am–7pm local timezone by default.
