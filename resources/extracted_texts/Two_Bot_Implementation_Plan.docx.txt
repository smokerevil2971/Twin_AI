4. Simplified Two-Bot Architecture

4.1 System Overview
Two independent bots sharing a common FastAPI backend, PostgreSQL database, and ChromaDB vector store. No frontend. Owner interacts via WhatsApp and direct API calls.


4.2 Bot 1 — Broadcast Agent Flow
This bot handles outbound bulk messaging triggered by the business owner.

Owner calls POST /broadcasts with message template, client filter, and optional scheduled_at
FastAPI validates the request and queues a Celery broadcast task
Celery worker fetches all eligible recipients (opted_in=true, not messaged in 24h)
Messages are personalised ({{name}} substitution) and sent via Gupshup at max 80 msg/sec
Delivery receipts arrive at POST /webhooks/gupshup/delivery and update broadcast_recipients
Owner queries GET /broadcasts/{id}/report to see delivery summary

4.3 Bot 2 — Client Assistant Bot Flow
This bot handles all inbound WhatsApp messages from clients automatically, 24x7.

Client sends WhatsApp message to the business number
Gupshup posts inbound message to POST /webhooks/whatsapp
FastAPI verifies HMAC signature and looks up client by phone number
LangGraph agent runs: sanitise → rate limit check → language detect → embed → retrieve → generate
ChromaDB returns top-k relevant chunks (filtered: is_active=true)
LLM generates retrieval-only response (no hallucination — only answers from retrieved context)
Reply sent back to client via Gupshup. Conversation stored in PostgreSQL.
If confidence < 0.75, conversation is flagged — owner notified via email alert
